# LLM Wiki 발표 대본

목표 길이: 약 4분 30초

## 1페이지. LLM Wiki 소개

안녕하세요. 제가 발표할 프로젝트는 **LLM Wiki**입니다.

LLM Wiki는 AI와 나눈 대화를 프로젝트별로 저장하고, 태그와 검색으로 다시 찾고, 필요하면 마크다운으로 내보낼 수 있는 로컬 우선 지식 관리 앱입니다. 이 앱의 핵심 목표는 AI 사용 기록을 단순한 채팅 로그가 아니라, 나중에 다시 활용할 수 있는 개인 지식 자산으로 바꾸는 것입니다.

## 2페이지. 문제 정의

요즘은 기획, 개발, 학습, 문제 해결 과정에서 AI를 자주 사용합니다. 하지만 좋은 답변을 받아도 그 대화는 대부분 채팅창 안에 흩어져 있습니다.

시간이 지나면 어떤 프로젝트에서 어떤 질문을 했는지 찾기 어렵고, 코드나 의사결정 내용을 다시 문서화하기도 번거롭습니다. 그래서 LLM Wiki는 AI 대화를 한 번 쓰고 버리는 기록이 아니라, 장기적으로 축적 가능한 지식으로 남기는 것을 목표로 했습니다.

## 3페이지. 프로젝트 제작 과정 기록

이 프로젝트는 만드는 과정에서도 LLM Wiki의 개념을 실제로 사용했습니다.

화면 왼쪽 자료는 Obsidian Vault에 저장된 Codex 작업 로그입니다. 프로젝트를 구현하면서 Codex와 나눈 요청, 답변, 수정 과정, 결정 내용을 프로젝트별 로그로 남겼습니다.

또한 화면에 보이는 것처럼 프로젝트 안에 `SKILL.md` 파일을 두어 작업 방식 자체도 문서화했습니다. 예를 들어 큰 코드 수정이 필요할 때는 변경 범위와 영향을 먼저 확인하도록 규칙을 만들었습니다.

즉, 이 프로젝트는 AI 대화를 지식으로 저장하는 앱을 만들면서, 실제 개발 과정도 같은 방식으로 기록하고 관리한 사례입니다.

## 4페이지. 현재 구현된 핵심 기능

현재 앱은 AI 대화를 저장 가능한 지식으로 바꾸는 흐름을 중심으로 구현되어 있습니다.

사용자는 AI 채팅 화면에서 프로젝트를 선택하고 질문을 보낼 수 있습니다. 앱은 선택된 AI 제공자에게 요청을 보내고, 사용자의 질문과 AI 응답을 하나의 대화로 저장합니다.

저장된 대화는 자동 태그로 분류되고, 제목, 본문, 태그 기준으로 검색할 수 있습니다. 코드 블록이 포함되어 있으면 코드 스니펫으로 추출해 다시 활용할 수도 있습니다.

## 5페이지. 기술 결정 기준

이 프로젝트의 핵심 기술 결정은 사용자 통제권과 확장성을 기준으로 잡았습니다.

먼저 로컬 우선 구조를 선택했습니다. 사용자의 대화와 설정은 서버에 먼저 보내지 않고 기기에 저장합니다. 또한 사용자가 직접 API 키를 등록해서 사용하는 방식을 선택했습니다. 이렇게 하면 서버 운영 비용을 줄이고, 어떤 AI를 얼마나 사용할지 사용자가 직접 통제할 수 있습니다.

Flutter를 선택한 이유는 하나의 코드베이스로 Android, iOS, Web, Desktop까지 확장할 수 있기 때문입니다.

## 6페이지. AI 채팅 저장 흐름

AI 채팅 저장 흐름은 네 단계로 구성됩니다.

먼저 사용자가 프로젝트를 선택하고 메시지를 입력합니다. 그 다음 앱은 API 키, 이메일, 카드 번호처럼 보이는 민감정보를 저장 전에 마스킹합니다.

이후 현재 선택된 AI 제공자와 활성 API 키를 사용해 답변을 생성합니다. 응답이 성공하면 사용자 메시지와 AI 답변을 하나의 Conversation으로 저장하고, 제목과 태그를 자동으로 생성합니다.

API 키가 없거나 호출에 실패해도 프롬프트는 사라지지 않습니다. 앱은 안내 메시지나 오류 내용을 함께 저장해 사용자가 원인을 확인할 수 있게 했습니다.

## 7페이지. AI 제공자와 API 키 관리

이번 업데이트에서 중요한 부분은 여러 AI 제공자를 지원하도록 확장한 점입니다.

현재 앱은 Gemini, GPT 또는 OpenAI, Claude, Grok을 선택할 수 있습니다. 설정 화면에서 사용할 AI 제공자를 고르고, 각 제공자별 API 키를 저장할 수 있습니다.

API 키는 하나만 저장하는 방식이 아니라 Provider별 키 목록으로 관리합니다. 사용자는 여러 키 중 사용할 키를 선택하거나 삭제할 수 있고, 화면에는 보안을 위해 키의 일부만 마스킹되어 표시됩니다.

또한 모델 접근 오류나 할당량 오류가 발생하면 후보 모델을 순차적으로 시도하는 대체 흐름도 포함했습니다.

## 8페이지. 지식 라이브러리 관리

저장된 대화는 라이브러리 화면에서 다시 관리됩니다.

사용자는 전체 대화를 볼 수도 있고, 특정 프로젝트의 대화만 볼 수도 있습니다. 검색은 제목, 본문, 태그를 대상으로 동작하므로 예전에 저장한 보안 정책이나 코드 해결 과정을 빠르게 찾을 수 있습니다.

저장 후에도 대화 제목을 바꾸거나 다른 프로젝트로 이동할 수 있고, 필요한 경우 수동 태그를 추가할 수 있습니다. 삭제된 대화나 프로젝트는 바로 사라지는 것이 아니라 휴지통으로 이동하며, 다시 복원하거나 영구 삭제할 수 있습니다.

## 9페이지. 마크다운 내보내기와 Obsidian 연동

LLM Wiki의 또 다른 중요한 기능은 내보내기입니다.

앱은 모든 프로젝트 또는 특정 프로젝트를 선택해 마크다운으로 내보낼 수 있습니다. 내보내기 결과에는 프로젝트 정보, 생성일, 태그, 사용자 메시지, AI 응답, 코드 스니펫이 포함됩니다.

이 구조 덕분에 앱 안에서만 끝나는 지식이 아니라 Obsidian, Git, 문서 도구로 옮겨 장기적으로 보관할 수 있습니다. Codex 작업 기록을 Obsidian 노트로 동기화하는 스크립트도 함께 준비했습니다.

## 10페이지. 보안, 다국어, 로컬 저장

보안은 이 앱에서 부가 기능이 아니라 제품 신뢰의 전제입니다.

API 키는 화면에 그대로 노출하지 않고, 입력 시에는 숨김 처리하고 저장 후에는 일부만 보여줍니다. 앱 설정에는 민감정보 마스킹, 앱 잠금, 암호화 저장, E2EE 동기화 준비 항목이 포함되어 있습니다.

또한 기본 언어는 한국어로 설정했고, 사용자가 원하면 영어와 일본어로 변경할 수 있게 했습니다. 현재 단계에서는 대화와 설정을 보안 저장소 기반의 로컬 스냅샷으로 복원하고, 이후 대용량 운영 단계에서는 SQLCipher 기반 SQLite 구조로 확장할 수 있도록 경계를 잡았습니다.

## 11페이지. 업데이트된 WBS와 남은 작업

WBS도 현재 구현 상태에 맞춰 업데이트했습니다.

완료된 범위에는 Flutter 앱 기반, AI Provider 연동, API 키 링 관리, AI 채팅 저장, 라이브러리 검색과 태그, 휴지통, 마크다운 내보내기, 데모 영상 제작이 포함됩니다.

현재 남은 작업은 실제 발표 리허설과 최종 화면 점검입니다. 이후 확장 방향으로는 실제 생체 인증 연동, SQLCipher 테이블 전환, E2EE 동기화, 그리고 AI 기억 그래프 기능을 생각하고 있습니다.

## 12페이지. 마무리

정리하면 LLM Wiki는 AI 사용 기록을 그냥 흘려보내지 않고, 다시 찾고 연결하고 오래 남길 수 있게 만드는 앱입니다.

이 프로젝트에서 보여주고 싶은 핵심은 단순한 채팅 저장이 아니라, AI와의 대화를 프로젝트 문맥 안에서 관리하고, 검색 가능한 태그와 마크다운 문서로 바꾸는 전체 흐름입니다.

마지막으로 30초 데모 영상을 통해 설정, 질문 저장, 검색, 내보내기까지의 사용자 경험을 보여드리겠습니다.

감사합니다.

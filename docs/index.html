Problem

AI 대화는 쌓이지만 지식으로 남지 않는다

사용자는 매일 AI와 문제 해결, 코드 작성, 학습, 기획을 진행한다. 하지만 대부분의 대화는 채팅창에 흩어져 있고, 나중에 다시 찾거나 프로젝트 문서로 재사용하기 어렵다.

“AI 대화를 단순 소비가 아니라 장기적으로 축적 가능한 개인 지식 자산으로 만든다.”
Build Process

이 프로젝트 자체도 LLM Wiki 방식으로 만들었다

LLM Wiki는 단순히 AI 대화를 저장하자는 아이디어에 그치지 않았다. 이 프로젝트를 만드는 과정에서도 Codex와 나눈 작업 대화와 결정 과정을 Obsidian Vault에 저장해, 다시 찾을 수 있는 개발 기록으로 남겼다.

또한 프로젝트 안에 SKILL.md 기반 작업 규칙을 두어 큰 수정이 필요한 순간에는 변경 범위와 영향을 먼저 확인하도록 했다. 즉, AI 대화는 기록으로 남기고, 반복 작업 방식은 스킬 문서로 표준화했다.

Core Features

현재 앱은 AI 대화를 저장 가능한 지식으로 바꾸는 흐름을 구현했다

AI 채팅 생성 사용자 메시지를 선택한 AI 제공자에게 보내고 응답까지 함께 저장한다.
Provider / API 키 관리 Gemini, GPT, Claude, Grok 키를 저장하고 사용할 키를 선택한다.
프로젝트 기반 라이브러리 대화를 프로젝트 단위로 묶고 이름 변경, 이동, 삭제, 복원을 지원한다.
자동 태그 생성 프롬프트와 응답에서 주제어를 뽑아 검색 가능한 태그로 만든다.
검색과 코드 추출 제목, 본문, 태그 검색과 대화 속 코드 스니펫 추출을 제공한다.
마크다운 / Obsidian 프로젝트 정보, 태그, 메시지, 코드 블록을 마크다운으로 내보낸다.
Architecture Decisions

핵심 결정은 사용자 통제권과 확장성을 기준으로 잡았다

로컬 우선 구조 대화와 설정을 기기 보안 저장소의 로컬 스냅샷으로 먼저 복원한다.
사용자 API 키 직접 사용 서버 프록시 없이 사용자가 Provider와 키를 직접 선택하게 한다.
마크다운 내보내기 특정 앱에 묶이지 않고 장기 보관과 재가공이 가능하다.
플러터 채택 iOS, Android, Web, Desktop 확장을 하나의 코드베이스로 준비한다.
로컬 우선 ADR API 키 ADR 마크다운 ADR 플러터 ADR
Implemented Flow

AI 채팅은 질문, 응답, 태그를 하나의 지식 단위로 저장한다

사용자가 프로젝트를 선택하고 메시지를 보내면 앱은 민감정보를 먼저 마스킹한 뒤 선택된 Provider에 요청한다. 응답이 오면 사용자 메시지와 AI 답변을 한 대화로 묶고, 제목과 태그를 생성해 로컬에 저장한다.

API 키가 없거나 호출이 실패해도 프롬프트는 사라지지 않는다. 앱은 안내 메시지 또는 오류 내용을 함께 저장해 사용자가 원인을 확인할 수 있게 한다.
1. 입력프로젝트 선택 후 한국어 메시지 작성
2. 보호API 키, 이메일, 카드 번호 형태 자동 마스킹
3. 호출활성 Provider와 API 키로 AI 응답 생성
4. 저장프롬프트, 응답, 태그, 코드 스니펫을 Conversation으로 저장
Provider & API Keys

하나의 앱에서 여러 AI 제공자와 여러 API 키를 관리한다

Provider 선택 Gemini, GPT / OpenAI, Claude, Grok 중 사용할 AI 제공자를 설정 화면에서 선택한다.
API 키 링 Provider별로 여러 키를 저장하고, 현재 사용할 활성 키를 선택하거나 삭제할 수 있다.
보안 표시 키는 입력 시 숨김 처리되고, 등록 후에는 앞뒤 일부만 보이는 마스킹 형태로 표시된다.
Fallback 처리 모델 접근 오류나 할당량 오류가 발생하면 Provider별 후보 모델을 순차적으로 시도한다.

Security Model

보안과 언어 설정은 사용자가 통제하는 방식으로 설계했다

앱은 한국어를 기본 언어로 사용하고, 설정에서 영어와 일본어로 전환할 수 있다. 보안 측면에서는 API 키를 보안 저장소에 분리하고, 대화와 설정은 로컬 스냅샷으로 복원한다. SQLCipher 전환, 앱 잠금, E2EE 동기화는 확장 가능한 구현 경계로 남겨두었다.

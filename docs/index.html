Problem

AI 대화는 쌓이지만 지식으로 남지 않는다

사용자는 매일 AI와 문제 해결, 코드 작성, 학습, 기획을 진행한다. 하지만 대부분의 대화는 채팅창에 흩어져 있고, 나중에 다시 찾거나 프로젝트 문서로 재사용하기 어렵다.

“AI 대화를 단순 소비가 아니라 장기적으로 축적 가능한 개인 지식 자산으로 만든다.”
Core Features

첫 번째 개발 단계는 저장, 분류, 검색, 내보내기에 집중한다

AI 채팅 저장 대화와 메시지를 프로젝트 단위로 저장하고 다시 열람한다.
자동 태그 생성 본문 키워드를 기반으로 검색 가능한 태그를 생성한다.
코드 스니펫 추출 대화 속 코드 블록을 별도로 모아 재사용성을 높인다.
제목/본문/태그 검색 로컬 데이터에서 빠르게 필요한 대화를 찾는다.
마크다운 내보내기 Obsidian, Git, 문서 도구로 지식을 이동한다.
보안 설정 마스킹, 앱 잠금, 암호화 저장을 중심으로 설계한다.
Architecture Decisions

핵심 결정은 사용자 통제권과 확장성을 기준으로 잡았다

로컬 우선 구조 대화 로그를 서버에 저장하지 않고 디바이스에 먼저 저장한다.
사용자 API 키 직접 사용 운영 비용과 서버 경유 위험을 줄이고 사용자 통제권을 높인다.
마크다운 내보내기 특정 앱에 묶이지 않고 장기 보관과 재가공이 가능하다.
플러터 채택 iOS, Android, Web, Desktop 확장을 하나의 코드베이스로 준비한다.
로컬 우선 ADR API 키 ADR 마크다운 ADR 플러터 ADR
Security Model

보안은 기능이 아니라 제품 신뢰의 전제다

API 키 평문 저장 금지, 사용자 대화 로그 서버 저장 금지, Secure Storage, SQLCipher, 민감정보 자동 마스킹, 앱 잠금, 향후 E2EE 동기화를 기본 설계 기준으로 둔다.

Keychain / Keystore SQLCipher Local-first E2EE-ready
“사용자의 지식은 사용자의 기기에 먼저 저장된다.”
Development Plan

저장과 검색에서 지식 그래프로 확장한다

1 첫 번째 개발 단계: 저장 및 검색 로컬 DB, 프로젝트 분류, 태그, 코드 추출, 마크다운 내보내기.
2 두 번째 개발 단계: Obsidian 동기화 Vault 동기화, provider 확장, 백업/복원 경험 강화.
3 세 번째 개발 단계: AI 기억 그래프 대화와 지식 노드의 관계를 연결해 장기 기억 시스템으로 확장.
Closing

LLM Wiki는 AI 사용 기록을 나의 지식 체계로 바꾼다

발표에서는 문제 정의, 핵심 기능, ADR 기반 기술 결정, 보안 설계, 개발 단계 순서로 설명하고 마지막에 앱 데모를 보여준다.
